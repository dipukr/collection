Basic TypeScript

TypeScript is a typed superset of JavaScript. Variables can be explicitly typed or their types can be inferred.

let name: string = "Dipu";
let age: number = 30;
let active: boolean = true;

const country: string = "India";

Type inference

let name = "Dipu";     // string
let age = 30;          // number
let active = true;     // boolean
Tip: Prefer const when a variable will not be reassigned.

Primitive Types

let str: string = "hello";
let num: number = 100;
let bool: boolean = true;
let big: bigint = 100n;
let sym: symbol = Symbol("id");
let nothing: null = null;
let nothingElse: undefined = undefined;

any

any effectively disables type checking.

let value: any = "hello";

value = 10;
value = true;
value.foo.bar();

unknown

unknown is a safer alternative to any. You must narrow the value before using it.

let value: unknown = "hello";

if (typeof value === "string") {
    console.log(value.length);
}

Arrays & Tuples

Arrays

let numbers: number[] = [1, 2, 3];
let names: string[] = ["John", "Bob"];
let values: Array<number> = [1, 2, 3];

Array of objects

let users: User[] = [
    { id: 1, name: "John" },
    { id: 2, name: "Bob" }
];

Tuples

A tuple represents a fixed sequence of types.

let user: [number, string] = [1, "John"];

let employee: [number, string, boolean];
employee = [101, "Dipu", true];

Optional tuple element

let user: [number, string?];

user = [1];
user = [1, "Dipu"];

Objects

let user: {
    id: number;
    name: string;
    active: boolean;
} = {
    id: 1,
    name: "Dipu",
    active: true
};

Optional and readonly properties

let user: {
    id: number;
    name?: string;
};

let account: {
    readonly id: number;
    name: string;
};

Type Aliases

Type aliases allow you to give reusable names to types.

type User = {
    id: number;
    name: string;
    email: string;
};

const user: User = {
    id: 1,
    name: "Dipu",
    email: "dipu@example.com"
};

Optional and readonly properties

type User = {
    readonly id: number;
    name: string;
    email?: string;
};

Interfaces

Interfaces describe the structure of objects and are particularly common in Angular applications.

interface User {
    id: number;
    name: string;
    email: string;
}

Extending interfaces

interface Person {
    name: string;
}

interface Employee extends Person {
    employeeId: number;
}

const employee: Employee = {
    name: "Dipu",
    employeeId: 101
};

Multiple inheritance

interface A {
    a: string;
}

interface B {
    b: number;
}

interface C extends A, B {
    c: boolean;
}

Type vs Interface

FeatureTypeInterface
Object shapesYesYes
Union typesYesNot directly
Intersection typesYesVia extension
ExtendingVia intersectionsVia extends

Union & Intersection Types

Union types

A union means the value can be one of several types.

let value: string | number;

value = "hello";
value = 100;

type Status = "PENDING" | "APPROVED" | "REJECTED";

let status: Status = "PENDING";

Intersection types

An intersection combines multiple types.

type Person = {
    name: string;
};

type Employee = {
    employeeId: number;
};

type EmployeeDetails = Person & Employee;

const employee: EmployeeDetails = {
    name: "Dipu",
    employeeId: 101
};
Remember: A | B means A OR B, while A & B means A AND B.

Enums

enum Status {
    PENDING,
    APPROVED,
    REJECTED
}

let status: Status = Status.PENDING;

String enums

enum Status {
    PENDING = "PENDING",
    APPROVED = "APPROVED",
    REJECTED = "REJECTED"
}

Functions & Arrow Functions

Function syntax

function add(a: number, b: number): number {
    return a + b;
}

function printName(name: string): void {
    console.log(name);
}

Optional parameters

function greet(name?: string): void {
    console.log(name);
}

Default parameters

function greet(name: string = "Guest"): void {
    console.log(name);
}

Rest parameters

function sum(...numbers: number[]): number {
    return numbers.reduce((a, b) => a + b, 0);
}

Arrow functions

const add = (a: number, b: number): number => {
    return a + b;
};

const addShort = (a: number, b: number): number => a + b;

const square = (x: number): number => x * x;

Function types

type Calculator = (a: number, b: number) => number;

const add: Calculator = (a, b) => a + b;

Classes & Object-Oriented Syntax

TypeScript classes are similar to Java classes.

class User {
    id: number;
    name: string;

    constructor(id: number, name: string) {
        this.id = id;
        this.name = name;
    }

    greet(): void {
        console.log(`Hello ${this.name}`);
    }
}

const user = new User(1, "Dipu");
user.greet();

Constructor shorthand

class User {
    constructor(
        public id: number,
        public name: string
    ) {}
}

const user = new User(1, "Dipu");

Access modifiers

class User {
    public name: string;
    private password: string;
    protected role: string;

    constructor(
        name: string,
        password: string,
        role: string
    ) {
        this.name = name;
        this.password = password;
        this.role = role;
    }
}
ModifierMeaning
publicAccessible everywhere
privateAccessible only inside the class
protectedAccessible inside the class and subclasses
readonlyCannot be reassigned after initialization

Inheritance

class Animal {
    move(): void {
        console.log("Moving");
    }
}

class Dog extends Animal {
    bark(): void {
        console.log("Barking");
    }
}

const dog = new Dog();
dog.move();
dog.bark();

Abstract classes

abstract class Animal {
    abstract makeSound(): void;

    move(): void {
        console.log("Moving");
    }
}

class Dog extends Animal {
    makeSound(): void {
        console.log("Bark");
    }
}

Getters and setters

class User {
    private _name = "";

    get name(): string {
        return this._name;
    }

    set name(value: string) {
        this._name = value;
    }
}

const user = new User();
user.name = "Dipu";
console.log(user.name);

Generics

Generics allow reusable code while preserving type safety.

function identity<T>(value: T): T {
    return value;
}

const name = identity<string>("Dipu");
const age = identity<number>(30);

TypeScript can usually infer the generic type:

const name = identity("Dipu");
const age = identity(30);

Generic classes

class Box<T> {
    constructor(public value: T) {}

    getValue(): T {
        return this.value;
    }
}

const box = new Box<string>("Hello");
const numberBox = new Box<number>(100);

Generic interfaces

interface ApiResponse<T> {
    data: T;
    status: number;
    message: string;
}

const response: ApiResponse<User> = {
    data: {
        id: 1,
        name: "Dipu",
        email: "test@example.com"
    },
    status: 200,
    message: "Success"
};

Generic constraints

function getLength<T extends { length: number }>(value: T): number {
    return value.length;
}

getLength("Hello");
getLength([1, 2, 3]);

keyof

interface User {
    id: number;
    name: string;
    email: string;
}

type UserKeys = keyof User;
// "id" | "name" | "email"
function getProperty<T, K extends keyof T>(
    obj: T,
    key: K
): T[K] {
    return obj[key];
}

Type Narrowing & Type Guards

typeof narrowing

function print(value: string | number) {
    if (typeof value === "string") {
        console.log(value.toUpperCase());
    } else {
        console.log(value.toFixed(2));
    }
}

Custom type guard

interface User {
    name: string;
}

function isUser(value: unknown): value is User {
    return typeof value === "object"
        && value !== null
        && "name" in value;
}

if (isUser(value)) {
    console.log(value.name);
}

Discriminated unions

type Result =
    | {
        type: "success";
        data: string;
    }
    | {
        type: "error";
        message: string;
    };

function handle(result: Result) {
    if (result.type === "success") {
        console.log(result.data);
    } else {
        console.log(result.message);
    }
}

Utility Types

Partial

type UserUpdate = Partial<User>;

Makes all properties optional.

Required

type RequiredUser = Required<User>;

Readonly

type ReadonlyUser = Readonly<User>;

Pick

type UserSummary = Pick<User, "id" | "name">;

Omit

type UserWithoutId = Omit<User, "id">;

Record

type UserMap = Record<string, User>;

const users: Record<string, User> = {};

ReturnType

function getUser(): User {
    // ...
}

type Result = ReturnType<typeof getUser>;

Parameters

function add(a: number, b: number) {}

type Params = Parameters<typeof add>;
// [number, number]

Advanced TypeScript

typeof

const user = {
    id: 1,
    name: "Dipu"
};

type User = typeof user;

Type assertions

const value: unknown = "Hello";
const name = value as string;

Non-null assertion

const element = document.getElementById("name")!;

Null and undefined

let name: string | null = null;
name = "Dipu";

Optional chaining

user?.address?.city;

Nullish coalescing

const name = user.name ?? "Guest";
?? falls back only for null or undefined, while || also treats values such as "", 0, and false as falsy.

as const

const status = "PENDING" as const;

const config = {
    status: "PENDING",
    retry: 3
} as const;

satisfies

type Config = {
    url: string;
    timeout: number;
};

const config = {
    url: "/api",
    timeout: 5000
} satisfies Config;

never

function throwError(message: string): never {
    throw new Error(message);
}

Function overloading

function getValue(id: number): User;
function getValue(name: string): User;

function getValue(value: number | string): User {
    // implementation
}

Mapped types

type Optional<T> = {
    [K in keyof T]?: T[K];
};

Conditional types

type IsString<T> =
    T extends string
        ? true
        : false;

type A = IsString<string>; // true
type B = IsString<number>; // false

Template literal types

type Direction = "top" | "bottom";

type Position = `margin-${Direction}`;

// "margin-top" | "margin-bottom"

Modules

Named export/import

export class UserService {
}

import { UserService } from "./user.service";

Default export/import

export default class UserService {
}

import UserService from "./user.service";

Aliases

import { UserService as Service } from "./user.service";
Modern recommendation: ES modules are generally preferred over namespaces.

Async / Await & Error Handling

Promise

function getUser(): Promise<User> {
    // ...
}

Async / await

async function getUser(): Promise<User> {
    const response = await fetch("/api/user");
    return await response.json();
}

Error handling

try {
    // code
} catch (error) {
    console.error(error);
} finally {
    // always executes
}

Safely handling unknown errors

try {
    // ...
} catch (error) {
    if (error instanceof Error) {
        console.log(error.message);
    }
}

Angular-Oriented TypeScript Example

A typical Angular application might define API models using interfaces and enums:

export interface Factor {
    id: string;
    factorId: string;
    factorName: string;
    sellerName: string;
    buyerName: string;
    financierName: string;
    status: FactorStatus;
    dueDate: string;
    paymentDate?: string;
}

export enum FactorStatus {
    PENDING = "PENDING",
    APPROVED = "APPROVED",
    REJECTED = "REJECTED"
}

Service

export class FactorService {

    constructor(
        private http: HttpClient
    ) {}

    getFactors(): Observable<Factor[]> {
        return this.http.get<Factor[]>("/api/factors");
    }
}

Component

export class FactorComponent {

    factors: Factor[] = [];

    constructor(
        private factorService: FactorService
    ) {}

    loadFactors(): void {
        this.factorService
            .getFactors()
            .subscribe(factors => {
                this.factors = factors;
            });
    }
}

What to Learn First

If you are coming from Java and your goal is Angular development, focus on these concepts in roughly this order:

Fundamentals
let, const, primitive types, arrays, objects
Type System
type, interface, union, intersection
Functions
functions, arrow functions, optional/default parameters
Modern JS
destructuring, spread, rest, optional chaining
OOP
classes, modifiers, inheritance
Generics
generic functions, classes, interfaces
Type Safety
narrowing, guards, unknown, never
Advanced Types
utility, mapped, conditional types
Java → TypeScript mindset: Java applications often revolve heavily around classes and inheritance. TypeScript/Angular code frequently relies more on interfaces, type aliases, object shapes, functions, generics, unions, and modern JavaScript features.
